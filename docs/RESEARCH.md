> 3. 竞品在做什么 → [§3](#3-竞品两端夹击)

## 0. 三条贯穿全部调研的结论

1. **赛道空白，但空白可能是「有人试过、发现不值得」**。859 个开源仓库里没有一个在做「把一道题变成一张可改的物理模型」。活得久的物理仿真产品（PhET、Algodoo、NB 实验室）做的都是**通用实验台**，不是单题建模。
2. **空白意味着没有可抄的**。所以调研的价值不是「学谁做什么功能」，而是「哪个已解决的问题，恰好是我卡住的那个」。
3. **覆盖率是这个产品的生死线**。自动建模长期停在 10% 的话，它不是老师的日常工具，只是一个演示品。

## 1. 真题分布：主战场是 1011 道计算题

数据：**304 份试卷 / 4462 道题 / 21 年（2006–2026）**，全部来自公开 PDF 提取，非人工录入。

### 1.1 一句话

**建模服务的主战场是 1011 道计算题，不是 2627 道选择题。**

选择题占 58%，但其中只有 **8%** 需要动力学建模（其余是概念辨析、图像判读、史实、仪器读数）；计算题里 **78%** 需要建模。

### 1.2 可建模性（4462 道）

| 级别 | 数量 | 占比 |
|---|---:|---:|
| D1 可静态建模（画对一张图就够） | 1511 | 34% |
| **D2 可动力学建模（要跑起来）** | **1139** | **26%** |
| D0 不可建模 | 1118 | 25% |
| D3 需专门模块 | 694 | 16% |

按题型拆开，结论完全不同：

| | 选择题（2627） | 计算题（1011） |
|---|---:|---:|
| D2 可动力学建模 | 221（**8%**） | 785（**78%**） |

**选择题是「判断对错」，不需要跑；计算题是「求出来」，必须跑。这两件事对应两种产品，不能混着做。**

### 1.3 计算题的建模要素

**场分布**：无场（纯力学）61% · 磁场 21% · 复合场 E+B 11% · 电场 7%。
→ 纯力学六成，但**场类合计 39%**。

**约束频次**（分母 1011，可多选）：水平面 27% · **圆/弧轨道 15%** · 绳 10% · 斜面 10% · 杆 9% ·
板/车 7% · 弹簧 7% · **传送带 1.7%**。

**结构与判据**：含**临界**（恰好/至少/刚要）**46%**；含**多过程**（然后/进入/滑上）**37%**。

**组合复杂度**：场 × 约束 × 多过程共 **161 种**组合，前 15 种覆盖 62%，前 30 种覆盖 76%。

> **这直接判了两条路的死刑**：逐题做预置是死路（161 种），只做 8 个原型也是死路（覆盖不到三成）。
> 正确解法是「组件 × 可串联」，不是「原型枚举」。

### 1.4 三个推翻既有判断的发现

**① 传送带只有 0.6%——上一轮的判断错了。**
上一轮看完竞品后写过「传送带值得做，因为竞品有」。全量 4462 道题里含传送带的只有 26 道（0.6%），
计算题里 17 道（1.7%）。**竞品做传送带，可能是因为它按「实验/演示」组织内容，不是因为传送带是高频考点。**
按题量算，优先级应该排在绳（10%）、斜面（10%）、杆（9%）、板（7%）、弹簧（7%）之后。
> 教训：**用竞品功能当需求证据是不可靠的。**

**② 选择题不是主战场，但可能是老师更想要的。**
D1（不需要仿真、只需要画对一张图）题量是 D2 的 1.3 倍（1511 vs 1139）。这不意味着要转做画图工具，
但它意味着：同一个场景除了「播放」，还应该能「定格 + 标注 + 逐步揭示」。

**③ 覆盖率 11% 的原因不是原型少，是「结构复杂度」没被建模。**
理论上限：计算题中「力学 + 无场 + 约束命中现有组件」的有 295 道 = **29%**；
当时实测规则解析（`parseProblem`，已删除）只有 **11%**。这个 11% 是**旧基线**，现在由 AI 生成，口径不可直接比。
差距来自：多过程（37%）、双体/多体、约束串联（现有 `arcChain` 是 13 段折线近似）。

### 1.5 数据可信度（必须写在结论旁边）

| 维度 | 抽样人工核对准确率 | 主要错误 |
|---|---|---|
| 题型 | ≈88% | 图-选项选择题被漏判 |
| 知识模块 | ≈95% | 「双缝干涉」曾判成振动与波 |
| 可建模性 | ≈93% | 纯图像判读误伤定量图像题 |

**所以上面的百分比有 ±5–12% 的误差带。用来定优先级够，用来做精确断言不够。**
另有两个已知局限：6 卷题量 < 9（占 2%，早期版式异常）；**约束识别偏弱**，19.6% 计算题被判「无约束」，
其中一部分是漏识别——所以 §1.3 的约束占比是**下限**。

⚠️ **语料许可证 CC BY-NC 4.0（署名-非商业）**：现在完全免费可以，**一旦接广告或收费就不能再用**。
所以只做统计与短摘录，不复制题干全文进产品。

## 1.6 覆盖率：分母、天花板、边际收益

> 「覆盖所有高中物理大题」这句话没有分母就没法讨论。可复跑的分析：`node scripts/coverage.mjs`

**分母不是 4462，是 785。**

| 层 | 数量 | 说明 |
|---|---:|---|
| 全部真题 | 4462 | 58% 是选择题，不需要建模 |
| 计算题 | 1011 | 这才是"大题" |
| **其中 D2（可动力学建模）** | **785** | 真正需要"跑起来"的 |
| D3 需专门模块 / D0 不可建模 / D1 静态 | 226 | **本身不该用仿真** |

所以「100% 覆盖」在数学上就不成立——有 226 道计算题不是动力学题。

**785 道的结构分布**：

| 场 | 数量 | 占比 | 含临界 | 含多过程 |
|---|---:|---:|---:|---:|
| 无场（纯力学） | 438 | 56% | 203 | 136 |
| 磁场 | 179 | 23% | 88 | 69 |
| 复合场 E+B | 102 | 13% | 61 | 81 |
| 电场 | 66 | 8% | 26 | 21 |
| **合计** | **785** | | **378（48%）** | **307（39%）** |

物体数：单 276 · 双 360 · 多（≥3）只有 13。

**当前天花板**：纯力学 438 道的约束**全部**在已支持的基元里（水平面/斜面/圆弧/轨道/绳/杆/板/车/弹簧/传送带/滑轮/导轨），
所以结构上能建 = **56%**。注意这是"不超出能力"，不是"AI 一定建成"。

**往上走的边际收益**（每行是"提到这个维度的题数"，多维度会重叠，不能相加）：

| 加什么 | 涉及题数 | 备注 |
|---|---:|---|
| 临界的表达（不是"找临界"，是判据翻转 + 一键跳到临界点） | 378 | **48% 的题含临界** |
| 多过程串联（build 更好用 + 组件参数槽） | 307 | 39% |
| 场类：速度空间相图 + 磁场几何求解 | 179 | 磁场题难在几何，不在积分 |
| 复合场（E→B 交替、速度选择） | 102 | 现在只有两个独立预置 |
| 电场深化 | 66 | 其中点电荷叠加是解析题，本来就该拒绝 |

**结论**：

1. 100% 不可能（226 道不是 D2）。
2. 现在约 56%；到 **85%** 需要三个机制包（磁场几何 / 复合场 / 电场深化），每个都是数周 + 物理正确性验证。
3. 85% 之后边际收益断崖——剩下的是长尾组合，每加一个只赚几道题。
4. **所以"覆盖所有"不该是目标。** 真正的指标是「老师手上那道题，多大几率 10 秒内变成能拨的模型」，
   而它 = **题库命中率 × AI 建成率**。题库（确定能建）比生成（可能能建）更能直接提升体验——
   把 785 道里的高频题收进题库，用户点开就有，完全不依赖 AI。

> ⚠️ 这份语料只有结构标注、**没有完整题干**（`head` 字段中位 110 字，原题中位 689 字），
> 所以上面算的是「理论上限」。AI 的**实测**建成率得拿全文跑，见 [AI.md](AI.md) §6。

## 2. 开源生态：没有可站的基础设施，但有一个关键发现

方法：GitHub 搜索 API，63 条查询（topic + 关键词，中英文），采集 **859 个唯一仓库**，按 9 个维度分类后人工筛选。

**859 个里跟「物理建模 / 交互仿真 / 场景 DSL」真相关的不到 60 个**，其余是游戏引擎、科研仿真（CFD/PINN）、
机器人仿真。**这个赛道没有成熟的开源基础设施可站。**

### 2.1 最值钱的发现不是功能，是「换一种求解方式」

**[myphysicslab](https://github.com/myphysicslab/myphysicslab)** ★453 · TypeScript · **Apache-2.0** · 530 文件。
Erik Neumann 的教学物理库，技术栈一样（TS + Canvas 2D），领域一样（2D 物理教学仿真）。

它的 `src/sims/roller/` 是「球在轨道上」的标准解法：`AbstractPath` 参数化路径 + `CirclePath` /
`LoopTheLoopPath` / `SpiralPath` / `CustomPath` + `RollerFlightSim`（球会飞离）。

**可借鉴的是判断，不是代码**：轨道应该是**解析路径 + 1D 弧长**，球的状态只有 `(p, v)`，
x/y/ke/pe 全是 computed。这样「脱离轨道」变成 `p` 超出 `finishT`，而不是碰撞检测。
代价是 7–10 人日的架构级改动，**前提是现有 `track` 理想约束（见 [PHYSICS.md](PHYSICS.md) §4）不够用**。

### 2.2 解析圆弧 vs 折线

同一个仓库的 `CircularEdge` 是**解析圆弧**（知道圆心直接构造；两端点重合自动识别整圆）。
我们的 `arcChain` 用 13 段折线近似 + 接触碰撞。

**这一条不用单独做**——如果走 §2.1 的 1D 路径，圆弧天然是解析的，它是那个方案的副产品。

### 2.3 看了但决定不要的

| 项目 | 为什么不要 |
|---|---|
| solvespace（参数化 CAD + 几何约束求解器，GPL-3.0） | 过度工程。「圆弧与斜面在连接点相切」是个两行公式，不值得引入求解器；GPL 还会传染 |
| rete / litegraph（节点图编程） | 我们是「拖组件 + 检查器」，不是数据流编程。会把产品变成编程工具 |
| manim（动画即代码） | 要交互不要预渲染视频。但它的「一个参数绑定到视觉、改参数即重画」和 `layout()` 是同一件事，概念可参考 |
| principia / Algodoo | 说明「自由搭建」品类成熟，但**全是游戏**——恰好印证了这个品类天然滑向玩 |
| AirsupHQ/machine-skill（一句话生成 HTML 仿真） | 反例。没有判据、不可编辑。这条路已经很挤，而且不解决「可改」 |

### 2.4 一个数据源候选（谨慎）

[cn-math-taxonomy](https://github.com/xiaoyang111222/cn-math-taxonomy) ★2,944 · CC BY-NC 4.0：
高中物理 177 个知识点 + **708 道题**。价值是当**负样本语料**——现在 `unsupported` 闸门只见过十几道题。
但它的 README 自己声明「AI 生成的初稿，未经教师审核」，质量不能当真值；许可证同样非商业。
**建议：抽 50 道只测一件事——生成链路会不会对不该建模的题静默给一个错模型。**

## 3. 竞品：两端夹击

### 3.1 OpenMAIC（清华 MAIC，MIT）：仿真比我们弱，编排比我们强

| | OpenMAIC | Slogan |
|---|---|---|
| 输入 | 任何主题 / 文档 | 一道具体的物理题 |
| 产出 | 一整堂课（幻灯片 + 测验 + 仿真 + PBL） | 一张可运行、可改的物理模型 |
| 仿真怎么来 | **LLM 现生成 HTML**，塞进 iframe | Scene JSON + 真实物理引擎 |
| 物理对不对 | 不保证，没有判据 | 有判据、有 145 个断言兜底 |
| 体量 | Next.js + React + PostgreSQL，4351 文件 | 纯 TS + Canvas，454 KB |

**能借的是它「怎么把一堆操作串成一次讲解」**：它把课堂动作抽象成 `Action`，由一个 `ActionEngine` 统一执行，
并区分两种语义——`fire-and-forget`（spotlight / laser，派发完立刻返回）与 `synchronous`（speech / whiteboard，
必须等它做完）。这个区分正是「演示脚本」缺的那一层。

**明确不要借**：LLM 现生成 HTML（等于放弃 Scene JSON 这个唯一资产）、它的技术栈、
多智能体课堂 / TTS / 白板 / PBL（TTS 是持续变动成本，与「完全免费」冲突）。

**一个反向机会**：OpenMAIC 的 `interactive` 场景就是「iframe `srcDoc` 的完整 HTML 文档」。
如果我们能把 Scene 导出成单文件 HTML + 四个 postMessage 监听，它天然就是一个 OpenMAIC 的 widget——
这可能是最省力的分发路径。

### 3.2 中文仿真合集（physics-lab-suite）：值得当竞品清单，不是技术参考

★2 · 纯静态单文件 HTML · 7 个实验室。星数低说明**可能没有真实用户**，只当「别人想到了哪些场景」看。

值得抄的两点：**慢放 + 图表指针同步**（讲课刚需）；**写死的性能预算**（30 FPS 上限 / DPR ≤ 1.5 / 离屏暂停）。
明确不抄的：规范解答卡（和「不判对错、不替代老师」冲突）。

## 4. 为什么不做课件

触发：一个很有力的批评——「课堂即时建模流程太长，应该改成备课时做课件」。

**流程批评成立**（拍照 → 登录 → 打开 → 等识别 → 调参数，哪怕 90 秒，也是在几十个学生面前沉默 90 秒），
**但「做课件」作为定位不成立**——不是难，是那个位置已经有人站了十年。

| 指标 | 数值 |
|---|---|
| 希沃交互智能平板出货份额 | **44.5%**（2024） |
| 活跃教师 | **700 万**（2025 H1，同比 +70 万） |
| 累计课件 | **15 亿份**（2025-06） |
| 覆盖教室 | 300 万间 / 20 万所中小学 |

硬件预装 + 账号体系 + 15 亿存量课件 + 教师培训体系，构成的是**渠道壁垒，不是产品壁垒**。
而且「课件里插一页能动的物理模型」这件事，希沃 + NB 实验室已经做了十年
（NB 官方 2024 年还在讲「一键插入 NB 实验，不用频繁切换页面」——这正是我们想解决的那个问题）。

**真正要改的不是「做什么」，是「产出物的复用单位」**：从「一道题的模型」改成「一个可复用的讲法」。
这条推论后来落成了「建模库存成文件夹 + 组件可复用」。

> ⚠️ 证据分级：希沃「300+ 实验模板」只有百科一个口径，官网功能列表没写，**置信度降一级**；
> 但「希沃里有物理仿真」有多源侧面印证。你可以 30 秒自己核实：装希沃白板5 → 新建课件 → 看「学科工具」。

## 5. 能不能搬进希沃：能，但要官方配合

**老师实际用什么**：讲课 + 批注主要发生在一体机上的**希沃 / 鸿合白板**里，不是浏览器里。
（教育 IFPD 前五合计 85.9%，希沃 + 鸿合国内前二。）

这也说明：**我们做批注是在替希沃补位，不是差异化**——所以批注只做「指出某处」的轻量墨迹，不做白板。

**技术上能搬进去**：希沃有官方插件体系（`EasiNote/EasiPlugin.Sample`），Web 插件用 CEF，
能嵌进课件页、有 js API、内容页就是普通网页。

**但**：插件要希沃官方生成、要线下谈、要**企业主体**。个人主体现在做不到。

**所以路线是**：短期做独立产品（Web 备课 + 小程序分发 + 轻量批注）；中期有老师用户后去 open.seewo.com
摸申请条件、攒案例；长期有企业主体再申请接入——到那时定位是「希沃缺的物理动态模型内容源」，
不是「另一个白板」。

> 未确认项：Web 内容元素能否跑 Canvas 交互；鸿合是否有开放平台（没找到 ≠ 没有）。

## 6. 建模表示问题的既有解法（2026-10-26 补）

前面的调研回答"该做哪些题"。这一节回答另一个问题：**"怎么表示物理模型"这件事，别人解到哪一步了。**

结论：**有 25 年的成熟答案（Modelica），但它解决的不是我们这个问题**——而且它反过来验证了我们的两个判断。

### 6.1 Modelica：工业界和学术界的标准

| Modelica 的做法 | 和我们的关系 |
|---|---|
| **组件 + 连接器（connector）+ connect 语句**：物理拓扑 = 组件连接图 | 一样。我们的 `Constraint` 就是连接器 |
| **基于方程、非因果**：写 `v = r*i` 而不是 `i = v/r`，求解方向由编译器定 | 我们没这一层（只有力的显式表达式） |
| **参数是一等公民**，UI 里就是表格和滑杆 | 一样 |
| 标准库约 **1290 个组件 + 910 个函数**（3.2 版） | 我们 18 个预置 + 7 种约束 |
| 需要编译器做 flattening + DAE 求解 | 我们用 planck 做数值积分 |

差别在输入：Modelica 给工程师建复杂系统（汽车、航空、能源），**它没有"题目"这个入口**。

### 6.2 Base Modelica：社区为机器可读专门做了简化子集

> 来源：ACM 论文《MLIR Dialects for DAE-based Modeling Languages》（一手，论文原文）

Modelica 社区明确认识到「机器需要简化子集」，正在标准化 **Base Modelica**——把人写的 Modelica
（带继承、connect 语法糖）压平成扁平、无语法糖、机器好处理的形式。

**这直接证明"给 agent 一个受约束的子集"是被验证过的路线**，不是我们瞎想。我们的 `AiPlan` / `BuildOp` 就是同一个思路。

### 6.3 LLM 生成这类模型的实证（2025–2026）

**① 零样本不行，精提示可以**

> 来源：《Automating Modelica Module Generation Using LLMs》（二手转述，chatpaper 摘要）

- GPT-4o **零样本生成不出可执行代码**
- Claude Sonnet 4 + 精心提示：基础逻辑块 **100%**、控制模块 **83%**；失败的输出要 **1–8 小时**人工修
- RAG 反而**导致模块选择错配**（把"与"检索成"或"），确定性硬规则检索更稳

→ 对我们的意思：**给 agent 的目录必须是硬编码清单，不要用向量检索。** 这跟 `archetypeCatalog()` 从 PRESETS 派生是同一个思路。

**② LLM 判断不了物理对不对**

同一篇的原话：**「当前的 LLM 无法评估仿真结果或验证行为的正确性，人工评估优于 AI 评估」**。

→ 所以那把"尺"必须是**确定性校验 + 数值验算**，不能是"让模型自己看看对不对"。
这条也修正了我之前"截图回读能替代一半人工验收"的乐观判断：截图能看**结构**，看不出**物理**。

**③ 从零发明 vs 在受信组件上配置，差距是数量级的**

> 来源：Modelon 官方博客《From Intent to Insight》（一手，厂商自述）

| | 从零开始 | 在已验证的库上配置 |
|---|---|---|
| 结果 | 物理上合理，**但不能当生产用** | **decision-grade**（可交付的工程结论） |
| 原话 | "plausible is not the same as trustworthy" | **"AI 没有猜物理，它加速了配置、分析和解读"** |

→ 印证我们的分层：**agent 该在受信组件上做配置，不该凭空发明物理。**

**④ 还有人在做"agent 修模型"**

> 来源：MODELS 2026 博士课题《Automated Modelica Model Repair Using Generative AI》（一手，论文摘要）

用 agentic LLM 在「编译/仿真反馈回路」里定位并修补 Modelica 模型。注意：那是**修已有模型**，
不是**从题干建模型**——我们的空位仍然在。

### 6.4 最接近我们的产品：Physion

浏览器 2D 物理，教育定位，免费。能力组合是：画形状 → 连关节/弹簧 → 播放；
**Property Editor** 改重力/摩擦/密度/劲度系数；**给任意物体挂 JavaScript**（Node Script）；场景可分享。

- 它解决表达力的方式是**脚本**——也就是我们评估后决定避开的那条路。
- 为什么它可以用而我们不行？**它是 sandbox（用户自己搭），我们是 translator（题目进来、模型出去）。**
  沙盒里用户会写代码；我们的用户是老师，不会为了改一个摩擦系数去读 JS。
- 细节很说明问题：Physion 官网的"即将支持"里写着 **Custom UI components (sliders, buttons)**——
  **连它都还没做到"任意属性自动出滑杆"**，这正是我们要做的差异化。

### 6.5 开放领域（电路板）怎么解：SPICE

> 来源：NI 白皮书《SPICE Simulation Models》（一手，厂商文档）

答案不是"一套通用属性"，而是**每个器件一张模型卡（model card）+ 器件库**。器件越多库越大，结构不变。

→ 印证：电路那种开放领域要换架构（领域包），不是把参数表加长。
高中物理的属性集是**封闭**的（二十来个数），所以表驱动可行。

### 6.6 所以我们抄什么、不抄什么

**抄**：Modelica 的 connector（→ 我们的 `ports.ts`）、Base Modelica 的"机器子集"（→ `BuildOp`）、
相容性分析（→ `validate.ts` 的自由度分析）。

**不抄**：方程求解（DAE + flattening，给多物理场工程师的）、脚本（牺牲的正是"老师能改"）。
