# 基础物理建模组件体系

> 你说这部分「很关键，直接影响到产品是否好用」——同意。这份文档要定的不是「有哪些组件」，而是**组件的抽象边界**：什么该做成组件、什么该做成参数、什么该做成判据。
> 依据：`docs/GAOKAO-20Y-CLASSIFICATION.md`（304 卷 / 4462 题）的实际分布。

---

## 0. 核心主张

**组件 = 一个物理条件，不是一件东西。**

这是和 Algodoo 分道扬镳的地方，也是「不预设教学法」原则在组件层的体现：

| | Algodoo / 游戏物理 | Slogan |
|---|---|---|
| 组件是 | 圆、方块、齿轮、绳子（**物件**） | 光滑、恰好、匀强、轻绳（**条件**） |
| 用户想的是 | 「我要画一个圆」 | 「这题说斜面光滑、物块恰好不下滑」 |
| 组件的价值 | 能拼出任何东西 | **能一句话对应一个题设** |

**推论**：组件的参数名必须来自题干用词（θ、μ、v₀、R、m、k、L），不能来自引擎（density、restitution、damping）。

---

## 1. 四类角色 + 一类观测

组件按「在物理上扮演什么」分五类，**不是按力学/电磁分**：

| 角色 | 定义 | 是否参与动力学 | 例子 |
|---|---|---|---|
| **主体 Matter** | 有质量、会被力推动的东西 | ✅ | 质点、小球、滑块、板、带电粒子 |
| **环境 Environment** | 不参与动力学，但作用于主体 | ❌ | 重力、匀强电场、匀强磁场、点源场、介质阻力 |
| **约束 Constraint** | 限制主体能去哪 | 部分（可移动的约束参与） | 地面、斜面、圆弧、绳、杆、弹簧、导轨、滑轮 |
| **判据 Criterion** | 检测「某事是否发生」 | ❌ | 脱离、到达、穿出、相遇、碰撞、守恒 |
| **观测 Observer** | 把状态读出来给人看 | ❌ | 轨迹、矢量、图表、能量条、探针 |

**为什么这个分类重要**：它决定了面板分几组、序列化怎么写、组合规则怎么校验。按力学/电磁分会让「同一个组件出现在两个分类里」（比如带电小球），按角色分不会。

## 2. 组件清单（带参数与真题频次）

### 2.1 主体（4 个）

| 组件 | 参数 | 覆盖的题干说法 |
|---|---|---|
| **质点** | m、q(可选)、位置、v₀(大小+方向) | 物块、小球（不滚）、带电粒子、电子 |
| **刚体·圆** | m、r、q(可选)、是否滚动、μ、位置、v₀ | 滚动的球、圆柱、轮 |
| **刚体·矩形** | m、w、h、角度、μ、位置、v₀ | 滑块、木板、薄板、车厢 |
| **刚体·多边形** | 顶点集、m、μ、位置、角度 | 斜面体、楔形、半圆槽本体、挡板 |

**关键设计：`q` 是可选字段，不是独立组件。** 带电小球 = 质点 + q≠0。这样「电场中的小球」不需要新组件，也不需要新面板。

**关键设计：`是否滚动` 是刚体·圆的一个开关**，不是一个新组件。关掉 = 圆盘平动（I=0 效果），打开 = 实心球纯滚动（I=2/5 m r²，`a = 5/7 g sinθ`）。这已经是 v4.1 的决定（DECISIONS §18），要延续。

### 2.2 环境（5 个）

| 组件 | 参数 | 说明 |
|---|---|---|
| **重力场** | g（默认 9.8，可切 10 / 月球 1.6）、方向 | 全局唯一，不是「可添加组件」 |
| **匀强电场** | E、方向、**作用区域（可选）** | F = qE |
| **匀强磁场** | B（**带符号，正=垂直纸面向外**）、**作用区域（可选）** | F = qv×B，必须用速度旋转积分（DECISIONS §3） |
| **点源场** | 源体 id、k（库仑或引力）、可正负 | F = k q₁q₂/r² 或 k m₁m₂/r² |
| **介质阻力** | 系数 c、阶次（一次/二次） | 空气阻力 |

**两个关键设计**：

1. **磁场在 2D 里只有 Bz 一个自由度**。高中物理的匀强磁场一律垂直纸面，所以参数就是「大小 + 正负（向里/向外）」，不需要三维方向。这比暴露 (Bx, By, Bz) 好用得多，也避免了「为什么 B 有方向但看不出」的困惑。

2. **「作用区域」是可选的**。不加区域 = 全场；加区域 = 有界场（磁场只存在于某个矩形/圆内）。**这是高考题的高频结构**（「磁场仅分布于两个相同且正对的半圆形区域」），现在 `Region` 已经有了，但面板上没有入口。

### 2.3 约束（6 个 + 2 个特殊）

| 组件 | 参数 | 真题频次 | 退化关系 |
|---|---|---:|---|
| **斜面** | θ、L、μ、位置 | 10%（+水平面 27%） | **θ=0 → 水平面** |
| **圆弧/圆轨道** | R、圆心角、μ、内侧/外侧、位置 | **15%** | 圆心角→0 退化为直线 |
| **板** | m、L、**μ上 / μ下**（分开）、位置 | 7% | m→∞ → 地面；μ上=μ下 → 单面 |
| **绳** | 长度、是否可松弛、两端锚点 | 10% | 长度固定 + 不可松弛 → 杆 |
| **杆** | 长度、是否可绕端转、两端锚点 | 9% | — |
| **弹簧** | k、l₀、阻尼、两端锚点 | 7% | **k→∞ → 杆** |
| 导轨（prismatic） | 轴、行程、锚点 | 气缸/滑块槽 | 行程→∞ → 直线 |
| 滑轮 | 比值、两段绳长、地面锚点 | 连接体 | — |
| ~~传送带~~ | v带、μ、L | **1.7%** | 低优先级 |

**这张表最重要的一列是「退化关系」**：6 个组件 + 参数退化，覆盖了约束出现频次的 **85%**（水平面 27 + 圆弧 15 + 绳 10 + 斜面 10 + 杆 9 + 板 7 + 弹簧 7）。

**这就是覆盖率的真正杠杆**——不是加更多组件，是让已有组件能退化。

### 2.4 判据（6 个 + 1 个新增）

已有：`detach`（脱离）、`reach`（到达）、`escape`（穿出）、`coincide`（相遇）、`collide`（碰撞）、`conserve`（守恒）

**建议新增 `threshold`（临界）**：

```ts
{ id: string; kind: 'threshold'
  /** 扫描哪个参数（可以是 params 里的任意键） */
  param: string
  from: number; to: number
  /** 观察哪个判据的翻转 */
  watch: string          // criterion id
  /** 二分精度 */
  eps?: number
}
```

**为什么需要它**：现在 `scene.search` 只支持「一个参数 + 一个判据 + 硬编码的 min/max」，而且每个场景要手写一条。而**46% 的计算题含临界**——这是最高频的结构，却只有最窄的实现。

> **实现说明（v5.4）**：没有把 `threshold` 做成新的 criterion kind，而是做成**通用的搜索 spec**（`packages/core/src/threshold.ts`）。
> 理由：临界不是「每帧判断的谓词」，是「扫一个参数看某个判据在哪翻转」——它属于搜索层，不属于判据层。
> `thresholdSpec()` 生成的对象与旧 `scene.search` **完全同构**（`{path,label,min,max,criterionId}`），所以搜索链路、分享、UI 都不用改；
> 参数区间来自 `PARAM_META`（题干用词，0/1 开关不进来），判据从场景现推。预置里手写过的同一条仍然优先（带理论值与精选区间）。

通用化之后：任何场景 + 任何参数 + 任何判据都能「找临界」，不需要为每道题写 `search`。

### 2.5 观测器（5 个 + 1 个新增）

已有：`trail`、`vector`、`chart`、`energy`、`probe`
**新增 `phase`**（相图，见 `MODELING-OSS-REVIEW.md` §3）：`chart` 的 `axis` 加一个 `'phase'` 取值，`quantity` 加 `vx`/`vy`。

## 3. 七条设计原则

### 原则 1：参数必须是学生能读的物理量

| ✅ 可以 | ❌ 不行 |
|---|---|
| θ = 30°、μ = 0.3、v₀ = 5 m/s、R = 0.5 m、k = 20 N/m | density、restitution、linearDamping、friction（引擎口径） |

**现有的一个违规**：气缸活塞用 `linearDamping` 表达「缓慢过程」。高中物理里没有这个量。建议改成「过程：缓慢 / 自由」，内部再映射到 damping。

### 原则 2：默认值必须是教材典型情形

- 斜面 **30°**（不是 37.5°）
- μ **0.3**（最常见题设）
- g **9.8**，可切 10
- 圆弧 **光滑**
- 板与地面 **光滑**、板与物块 **粗糙**

**理由**：老师打开就该看到「像一道题」的样子，而不是「像一张白纸」。

### 原则 3：一个组件最多 5 个参数

超过 5 个说明抽象错了。高中物理题里，一个物体同时可调的独立量很少超过 5 个。

**检查**：板有 m/L/μ上/μ下 = 4 个，合格；如果把「厚度、密度、颜色」也塞进去就超了。

### 原则 4：每个参数都必须能被一根滑杆驱动

因为产品核心交互是「改一个条件，看结果怎么变」（DECISIONS §30 的 T 指标）。

**不能驱动的参数**（如多边形顶点集）必须藏在二级入口，不进主面板。

### 原则 5：组件语义单一，不做「组合组件」

斜面 ≠ 斜面+圆弧。后者是**两个地形在连接点相切**（DECISIONS §16）。理由很实在：题目常要求「斜面粗糙、圆弧光滑」，一个组件只有一个 μ 就表达不了。

**这条的代价**：用户要连两次。**收益**：任何分段摩擦的题都能建。

### 原则 6：每个组件必须有退化情形

见 §2.3 的退化列。这是「少组件覆盖多题」的唯一办法。

**实现要求**：退化必须是**参数连续变化**的结果，不是隐藏开关。θ 从 30 拖到 0，视觉上斜面变成水平面——这个过程本身就是教学内容。

### 原则 7：组合必须显式，不能连就明说

| 组合 | 规则 |
|---|---|
| 主体 ↔ 约束（接触） | 自动，无需连接 |
| 主体 ↔ 绳/弹簧/杆 | 需两个锚点；锚点可以是 body 局部坐标或世界坐标 |
| 约束 ↔ 约束（地形合并） | 只有「同侧端点距离 < 阈值」才允许合并 |
| 环境 ↔ 主体 | 场只作用于 `q ≠ 0` 的主体；有区域时只作用于区域内 |
| 主体 ↔ 主体（碰撞） | 需要 `contactPair`（μ、恢复系数），默认自动生成 |

**不能连时必须给一句话理由**，例如「圆形的轨道不能和矩形地形合并」——不要静默失败。

## 4. 优先级（按真题数据，不按直觉）

| 优先级 | 做什么 | 依据 | 现状 |
|---|---|---|---|
| **P0** | **让 6 个约束能退化**（θ→0、k→∞、m→∞、v带→0） | 退化后覆盖 85% 约束频次 | 部分有，面板没暴露 |
| **P0** | **`threshold` 判据通用化** | **46%** 计算题含临界 | 只有窄版 `search` |
| **P0** | **多过程串联**（精确圆弧，不折线） | **37%** 计算题含多过程 | `arcChain` 是 13 段折线 |
| **P1** | **场的「作用区域」面板入口** | 磁场 21% + 复合场 11%，有界场是高频结构 | `Region` 有，无入口 |
| **P1** | **匀强电场中的带电粒子**（解析器支持） | 电场 7% + 复合场 11% | 有示例，解析器明确拒绝 |
| **P1** | **磁场圆周 + 边界** | 磁场 21%（计算题第二大场） | 有示例，边界弱 |
| **P2** | 传送带 | **1.7%** | 无 |
| **P2** | 滑轮一般化（任意放置） | 连接体已够用 | Atwood 组件组 |
| **不做** | 电路、热力学过程、波形图 | D3 合计 16% | 明确拒绝是对的 |
| **不做** | 近代物理、光学定性 | D0 为主 | 明确拒绝是对的 |

**注意 P0 的三条都不是「加新组件」，而是「让已有组件更强」。** 这和 `GAOKAO.md` 里「1 建 8 拒」的教训一致：问题不在组件少，在组件太专用。

## 5. 每个组件的验收标准

一个组件算「做好了」，要同时满足：

1. **能建**：`parseProblem` 能识别出它（或明确说不能）
2. **能跑**：`tests/acceptance.test.ts` 里有对应的物理验收（误差 < 3%）
3. **能改**：面板参数 ≤5 个、每个都能滑杆驱动
4. **能退化**：至少一个参数能退化到另一个组件
5. **能分享**：改完参数后分享串仍能压回 `p1.`（≤250 字符）
6. **能解释**：检查器里有一句话说明「这个组件在物理上代表什么」

**第 6 条容易被忽略但很重要**：老师看到一个「导轨」组件，如果不知道它对应题干的哪种说法，就不会用。

## 6. 组件不该做的事

| 不做 | 理由 |
|---|---|
| 内置教学提示（「这里要注意…」） | 违反「不提供怎么讲」原则 |
| 内置答案 / 标准解法 | 同上，而且会出错 |
| 组件级「预设组合」（如「斜面+圆弧」做成一个组件） | 见原则 5 |
| 组件级动画 / 音效 | 会滑向游戏 |
| 组件级权限（免费/付费） | 付费墙会破坏「免费工具」定位 |

## 7. 一个尚未想清的问题

**「半圆槽（可移动）」这类「约束本身参与动力学」的组件，算约束还是主体？**

- 物理上它是主体（有质量、会被推动）
- 交互上它是地形（用户想的是「槽」，不是「一个会动的物体」）

现在的做法是：槽是 `static` 地形 + 一个 `track` 约束，用户双击可切成 `dynamic`（README 里写「要固定槽，选中槽把角色改成地形即可」）。

**结论（2026-10-24 修正）**：不做面板开关，**用外观区分**——`kind === 'static'` 的物体在接触面外侧画 45° 剖面线（教材固定端符号），`rigid`/`particle` 不画。

理由：开关要求用户先知道「有这个概念」，外观直接告诉他「现在是什么」。详见 `VISUAL-GRAMMAR.md` §1、§4。

**唯一的缺口是「怎么改」**：保持双击切换，但选中时在物体旁浮一个只读徽标「固定」，提示这个东西可以改（`VISUAL-GRAMMAR.md` §5）。

这也印证了原则 1：**角色不是用户该理解的概念，物理条件才是**——所以要用视觉表达物理条件，而不是让用户操作「角色」这个概念。
