# 产品执行方案 v1

> 2026-10-24。本文档是今天全部讨论的收敛结果，也是接下来做事的唯一入口。
> 所有决策的原始依据在各专题文档里（见 §9 索引），本文只保留「做什么、按什么顺序、怎么算做完」。

---

## 0. 一页纸

**一句话**：把一道高中物理题，变成一张能拨动的模型；建好的模型能打包成一个链接发出去。

**三个不做**（今天逐个定下的）：
1. **不做课件**——位置被希沃 + NB 占住（`POSITIONING-REVIEW-COURSEWARE.md`）
2. **不做「讲法」**——不替老师决定怎么讲（`DECISIONS.md` §30）
3. **不做白板**——批注只做「指出某处」，不做板书（`ANNOTATION-DESIGN.md`）

**一条产品原则**（判据，用来否掉后续一切想法）：

> **只提供「物理情境」，不提供「怎么讲」。**
> 新增功能若在表达「先这样、再那样」→ 不做；若在扩展「这个情境能被怎么摆弄」→ 做。

**唯一核心指标**：

> **T = 从「我手上有这道题」到「模型在屏幕上能拨」的秒数。**
> 课堂可接受 **≤ 10 秒**，备课可接受 **≤ 60 秒**。

**未来 6 周只做四件事**：条件表单、假设可勾选、视觉语法、临界判据通用化。
> （2026-10-25 更新：条件表单与临界判据通用化都已删除；假设可勾选与视觉语法保留。）

## 1. 产品定义

### 1.1 是什么

| | |
|---|---|
| 输入 | 一道题（文字粘贴；图片识别推迟，见 §6） |
| 输出 | 一张可运行、可手改的物理模型（Scene JSON） |
| 兜底 | 生成不保证对，所以**手动改模型是产品底线**；生成不了必须明确拒绝，不能给错模型 |
| 组织 | 一个链接可以装多个模型（场景集） |
| 讲解 | 模型上可以临时批注（一支笔） |

### 1.2 不是什么

不是题库、不是课程、不是实验复现、不是白板、不是课件、不判对错、不做 A/B 对照。

### 1.3 三个时刻，一套数据

```
备课（Web，键鼠大屏）
  题目 → 模型 → 改参数 → 存进场景集 → 得到一个短链接
        ↓ 同一个链接
课堂（Web 全屏）
  打开链接 → 点第 3 个 → 播放 → 批注 → 换第 4 个
        ↓ 同一个链接
课后（小程序 / 微信卡片）
  学生打开，自己拨参数、自己看判据
```

**关键：三个时刻共用同一份 Scene JSON，不导出、不转换、不重复劳动。**

### 1.4 用户

- **老师**：备课 + 课堂演示。决定口碑，是传播节点。
- **学生**：课后自学、群里点开。决定规模。
- 老师不是「日活用户」——物理课一周 12 节，真实使用每周 2–5 次，是**深度使用**。所以这个产品不靠日活，靠「备课一次、用一学期」。

## 2. 现状盘点（v5.3）

### 2.1 已具备

| 能力 | 状态 |
|---|---|
| 题目 → 模型 | 规则解析 v0，8 类原型，文字粘贴可用 |
| 模型编辑 | 拖拽/旋转/速度手柄、检查器、世界面板、组件库（5 个）、多过程链 |
| 物理 | Planck 刚体 + 场力（qE、qv×B）+ 库仑/引力 + 气体 + 滑轮；84 个测试，关键场景误差 <3% |
| 观测 | 轨迹、矢量、v–t、能量条、探针；6 类判据 |
| 双端 | Web + 小程序，UI 全 canvas 自绘，小程序包 407 KB |
| 分享 | `p1.` 紧凑串 74–185 字符；`s1.` 完整 JSON |
| **批注** | ✅ 今天刚做：一支笔 + 橡皮 + 清空，世界坐标、不进 Scene、9/9 验收通过 |

### 2.2 数据资产（今天新增）

- **4462 道真题分类**（304 卷 / 2006–2026），四轴：题型 / 模块 / 建模要素 / 可建模性。
- 三个可用于决策的数字：
  - 计算题占 23%（1011 道），其中 **77.6% 可动力学建模**；选择题占 58% 但只有 **8%** 需要建模。
  - 计算题里 **临界 46%、多过程 37%**。
  - 建模要素组合共 **161 种，前 30 种覆盖 76%**。

### 2.3 明确缺口（按影响排序）

| 缺口 | 影响 |
|---|---|
| **生成后纠错要 30–120 秒** | T 最大的隐藏成本，比「输入慢」更伤 |
| **没有「填参数就出模型」的入口** | 解析失败后只能手动拖拽，5 分钟起 |
| **临界判据只有窄版 `search`** | 46% 的计算题建不了 |
| **多过程只有折线近似** | 37% 的计算题精度不够 |
| **固定/可移动、粗糙、磁场方向看不出来** | 「形象」这个定位没落地 |
| 一个链接只能装一个模型 | 老师要发 5 条消息 |

## 3. 核心指标与度量

### 3.1 T 的分解

| 步骤 | 当前 | 目标 |
|---|---|---|
| 拍照/截图 | 3–5 s | 不变（图片识别推迟） |
| **图片 → 文字/要素** | **∞（未实现）** | 暂不解决，走文字/表单 |
| 粘贴文字 | 15–30 s | 不变 |
| 解析 | < 0.1 s | 不变 |
| **生成后纠错** | **30–120 s** | **≤ 2 s**（假设可勾选） |
| **没有入口时的手动搭建** | 3–5 min | **≤ 10 s**（条件表单） |

**结论：T 的两个瓶颈都不是「解析慢」，是「纠错」和「没有兜底入口」。** 这两件事都不需要 AI。

### 3.2 覆盖率指标（比 T 更根本）

T 再快，建不出来也没意义。用真题样本度量：

- **口径**：从 1011 道计算题里分层抽 30 道，人工判定「能建 / 需要什么能力才能建 / 不能建」。
- **当前估计**：力学 + 无场 + 约束命中现有组件的理论上限 **29%**，实测 **11%**（1/9）。
- **目标**：阶段一结束 ≥ 40%；阶段二结束 ≥ 55%。

### 3.3 只看三个数（第一个月）

1. **T（课堂路径）**：条件表单从点击到模型可拨，是否 ≤ 10 秒
2. **覆盖率**：30 道样本里「能建」的比例
3. **纠错次数**：一次生成平均要改几个假设

**不看**：UV、留存、日活。这个阶段样本量太小，看这些只会误导。

## 4. 路线图

三段，每段 2–3 周。**顺序依据是「先让建得出来、再让组织得起来、最后让讲得下去」**，不是人日多少。

### 阶段一：建得出来、建得快（约 12 人日）

> **执行记录（2026-10-24）**
>
> | # | 任务 | 状态 | 落地位置 | 实测 |
> |---|---|---|---|---|
> | 1.1 | 条件表单入口 | ❌ **已删除** | 曾实现于 `conditions.ts`，v5.5 按产品方向调整删除 | 见下方「方向调整」 |
> | 1.2 | 假设可勾选 | ✅ | `packages/core/src/assumptions.ts` + 状态条 chip | 4 类假设可切；改完分享串仍是 `p1.` |
> | 1.3 | 视觉语法第一批 | ✅ | `packages/render/src/renderer.ts` | 静态体 45° 剖面线；磁场 ×/· + 方向标签；带电 +/−；短边 <24px 不画 |
> | 1.4 | 临界判据通用化 | ❌ **已删除（2026-10-25）** | 曾实现于 `threshold.ts` + 找临界面板；按产品决定移除 | 判据（脱离/到达/碰撞…）保留，二分搜索入口不要了 |
>
> ### 方向调整（2026-10-24，v5.5）——**覆盖本文 §0 的入口假设**
>
> 条件表单做完后被明确否掉：**「这个没啥用，入口其实就是一个生成建模的入口」**。同时否掉空白画布与首页的示例卡片墙。
>
> 新结构（以本文 §4 的阶段一为准已被替换，此处为现行方案；v5.6 补了详情页与用户页）：
>
> ```
> 底部三栏：用户 / 题库 / 模型
> 题库（首页）→ 点一张题 → 题目详情（完整题干）→ 生成建模 → 模型（收藏夹，自建文件夹）
> ```
>
> - **题库** `packages/core/src/bank.ts`：15 道题（力学 11 / 电磁学 3 / 热学 1）；每条带 `expect`，`tests/bank.test.ts` 逐条验证「说能建的是不是真能建」，不出现「点了才知道建不了」。
> - **生成建模**：点题 / 贴题干两条都走 `parseProblem`；失败不关弹层、原地说明缺什么，题目记进「我的题目」。
> - **建模库** `packages/core/src/library.ts`：文件夹、移动、本地持久化（localStorage / `wx.setStorageSync`）、60 个上限、离开画布写回同一条。
> - **题目详情**（v5.6）：点题**不直接建模**，先看完整题干再决定——原话「点击后先看到完整题目，然后可以选择建模」。
> - **用户页**（v5.6）：本地数据统计 + 清空（带确认）+ 关于。没有账号体系。
>
> **这个调整顺带回答了两个旧问题**：
> - §3.1 里「没有兜底入口 → 手动搭 3–5 分钟」不再是主要矛盾——用户不要兜底入口，要的是「题库里点一下就有」。
> - §4 阶段二 2.1「场景集 `c1.`」被**本地建模库**部分替代（零后端、按文件夹分类）；跨设备同步与链接分享仍待做。
>
> 验收脚本：`node scripts/shots-bank.mjs`（16/16）、`node scripts/mp-verify.mjs`（小程序端 15 项，含题库生成与建模库）。
> 单元测试：`tests/{bank,library,assumptions-threshold}.test.ts`（24 项）。

| # | 任务 | 人日 | 交付物 | 验收标准 |
|---|---|---:|---|---|
| **1.1** | **条件表单入口** | 3 | 「选情境类型 → 填 3–5 个参数 → 出模型」，与「题目 → 建模」并列为主入口 | ① 10 类情境可选；② 5 秒内出模型；③ 全程不需要键盘（滑杆+点选）；④ 出的是普通 Scene，可继续改 |
| **1.2** | **假设可勾选** | 2 | 生成后的「假设」变成一行可点 chip，点一下即时重算 | ① 滑块/小球、光滑/粗糙、固定/可移动、有无阻力四类可切；② 纠错 ≤2 次点击；③ 改完分享串仍能压回 `p1.` |
| **1.3** | **视觉语法第一批** | 2 | 固定剖面线（`kind==='static'`）+ 磁场 ×/· 阵列 | ① 半圆槽固定/可移动一眼可辨；② `crossedFields` 看得出 B 的方向；③ 屏幕短边 <24px 时不画装饰 |
| **1.4** | **临界判据通用化** | 4–5 | `threshold` 判据：任意场景 + 任意参数 + 任意判据找翻转点 | ① 替换现有 `scene.search` 的硬编码；② 抽样 5 道临界真题能建且找得到翻转点；③ 结果仍显示 3 位有效数字 |

**为什么这四件排在最前**：
- 1.1 和 1.2 直接把 T 从「分钟级」压到「秒级」，且**零外部依赖**（不用 AI、不用 OCR、不用内容库）。
- 1.3 只有 2 人日，但它是「形象生动」这个定位第一次真正落地。
- 1.4 是覆盖率的最大单点（46%），且是已有能力的横向扩展，不是新建。

### 阶段二：组织得起来（约 8 人日）

| # | 任务 | 人日 | 交付物 | 验收标准 |
|---|---|---:|---|---|
| **2.1** | **场景集 `c1.`** | 4 | 一个链接装多个模型；Web 编辑 + 小程序只读列表 | ① 6 个场景 ≤900 字符；② 旧 `p1.`/`s1.` 链接继续有效；③ 含 `s1.` 场景时标「仅电脑可打开」；④ 超预算明说「带了 6/9 个」 |
| **2.2** | **约束退化** | 3 | 斜面 θ=0→水平面、弹簧 k→∞→杆、板 m→∞→地面 | ① 6 个约束各有一个退化用例；② 退化是参数连续变化的结果，不是隐藏开关；③ 面板上能看到退化后的读数 |

**为什么退化放这里**：6 个约束 + 退化覆盖 85% 的约束出现频次（水平面 27 + 圆弧 15 + 绳 10 + 斜面 10 + 杆 9 + 板 7 + 弹簧 7）。**这是覆盖率的第二个大杠杆，成本只有 3 人日。**

| **3.3** | 批注 L1 | 4–5 | 箭头 / 文字 / 圈（结构化批注） | ① 单个标注 ≤60 字符；② 箭头用虚线墨色，与力箭头区分；③ 带批注的场景不进场景集并提示 |

**3.1 必须先做**：如果半小时能修好入口断层，就不必上 1D 路径（架构级改动）。**先花 0.5 天省掉 8 天。**

## 5. 优先级依据

不是凭感觉排的，每条都有数据或指标支撑：

| 决策 | 依据 |
|---|---|
| 条件表单排第一 | T 的最大瓶颈是「没有兜底入口」；且它零依赖、5 秒、100% 成功 |
| 假设可勾选排第二 | 纠错 30–120s → 2s，是 T 里唯一能一个数量级改善的项 |
| 视觉语法排第三 | 2 人日换「形象」定位落地；固定/可移动、磁场方向现在完全看不出 |
| 临界判据排第四 | 46% 计算题含临界，是覆盖率最大单点 |
| 场景集排阶段二 | 它解决的是**组织成本**，不改变 T 的瓶颈 |
| 约束退化排阶段二 | 3 人日换 85% 约束覆盖，性价比高但不如前面紧急 |
| 传送带不做 | 全量 4462 题里只有 **26 道（0.6%）**——推翻了我之前基于竞品的建议 |
| 图片识别降级 | OCR/多模态按次计费，与「完全免费」冲突（L2 变动成本档） |

## 6. 五个待验证假设（都不需要写代码）

这五个假设如果有任何一个错，路线要改。**每个都能在 5–10 分钟内问出来。**

| # | 假设 | 怎么验 | 如果错了 |
|---|---|---|---|
| 1 | 老师会在课堂上打开一个网页工具 | 问 3–5 个物理老师：「你上课用触屏还是鼠标/笔？」 | 优先做 Web 全屏，放弃小程序课堂场景 |
| 2 | 老师愿意自己搭模型（而不只是用成品课件） | 「你上一次讲临界问题是怎么讲的？」 | 转向「预置模板 + 少量参数」，放弃自由搭建 |
| 3 | 一个链接装多个模型是刚需 | 「你平时怎么把题目发给学生？」 | 场景集降级为可选功能 |
| 4 | 老师会复用自己建的模型 | 「下届还讲这个吗？会想存下来吗？」 | 放弃「场景集」，只做即时分享 |
| 5 | 希沃能谈 | open.seewo.com 看申请条件 + 问商务 | 长期只做独立产品 |

**第 5 条不影响近期任何工作**，但决定 12 个月后的天花板。

## 7. 不做清单（写死，避免反复）

| 不做 | 依据 |
|---|---|
| 课件 / 课时结构 / 知识点串讲 | 位置被希沃占；且违反产品原则 |
| 教学步骤 / 讲解词 / 「讲法」 | 每个老师有自己的风格 |
| 白板功能（颜色/粗细/图层/荧光笔） | 会滑向希沃的战场 |
| 题库 / 作业 / 学情 | 另一个产品，撞学科网、智学网 |
| 电路计算、热力学过程、波形图 | D3 合计 16%，需要新求解器 |
| 近代物理、光学定性 | D0 为主，不需要建模 |
| 传送带 | 1.7%（计算题）/ 0.6%（全量） |
| A/B 对照 | v4.1 已删，是伪需求 |
| 账号体系 | openid 够用 |
| 云同步场景库 | 先用链接 + `.json` 导出；等老师说「换电脑找不到」再上 |
| LLM 生成 HTML 仿真 | 会丢掉 Scene JSON 这个唯一资产 |
