# 组件：由使用产生，不由产品穷举

> 2026-10-25。这条不是「加一个功能」，是**组件从哪来**的答案：不预置组件库，让用户在使用中把好用的组合存下来。

---

## 1. 问题

编辑器不可能预先穷举所有组合。真题里常见的是「两个球 + 一根绳 + 一个斜面 + 一个电荷」这种**临时组合**，
LLM 或别人分享的模型里更是会出现我们没见过的搭法。硬编码组件库永远追不上，而且每加一个组件都在赌「老师会不会用」。

反过来，**用户自己知道哪一坨好用**——他做出来一次、觉得顺手，就应该能存下来，下次直接用。

## 2. 什么是「一个组件」

一次**选中集**的抽取结果：

| 存什么 | 不存什么 |
|---|---|
| 物体（形状、质量、电荷、摩擦、初速度…） | 观测器（轨迹/图表/探针） |
| 它们之间的约束（绳/杆/弹簧/滑轮/轨道/导轨） | 判据 |
| 它们之间的气体系统（气缸 + 活塞） | 场与区域 |
| 组件需要的世界开关（库仑力 / N 体引力） | 相机与取景 |

**为什么不存观测器/判据/场**：那些是**场景级**的东西。一个「双球绳」组件插到磁场场景里，
不该把原来的轨迹观测器也带进去；场和区域更是跟具体位置绑定，跟着组件走只会制造困惑。

## 3. 怎么存

画布目前是**单选**，所以「存组件」不是框选，而是**从点中的物体出发，顺着约束把整段找出来**：

```
点中球 A  ──绳──  球 B         → 组件 = 球A + 球B + 绳
点中活塞  ──导轨── 气缸         → 组件 = 活塞 + 气缸
点中滑块（只有接触，没有约束）   → 组件 = 滑块
```

- 入口：选中物体 → 左侧「＋ 存为组件」
- 自动起名：`球 A + 球 B`（取标签，超过 3 个显示「等 N 件」），可改名
- 上限 16 个物体（防止把整个场景吸进来）、40 个组件

## 4. 怎么插

- 入口：左侧「组件」→ 列表 → 「插入」
- 插到**舞台中央**，所有 id 换成新前缀（`k<时间戳>-0`…），约束的两端跟着换名
- 插完自动选中，可以马上拖 / 改参数

## 5. 和「预置场景」的区别

| | 预置场景（preset） | 用户组件 |
|---|---|---|
| 有 `layout()` | 有：改 θ 会重排几何 | 没有：插到哪就是哪，参数靠检查器逐个改 |
| 分享 | `p1.` 短串 | 跟着建模库本地存（还没做导出） |
| 来源 | 我们写的 | 用户从任何场景里存出来的 |

**这条区别很重要**：预置场景是「参数化的模板」，组件是「一段现成的模型」。前者适合「一道题的典型情形」，
后者适合「我常用的一坨东西」。不要试图让组件也带 layout——那会把它变回预置。

## 6. 边界与风险

1. **坏模型也会被存下来**。LLM 生成的模型如果本身就是错的，用户存下来的就是错的。这是用户的选择，
   而且只存在本地——但意味着「组件库」不是质量背书，别在 UI 上暗示它是。
2. **跨设备不通用**。组件跟着建模库存在 localStorage / `wx.setStorageSync` 里，换设备就没了。
   要跨设备得先做导出/导入（和建模库是同一件事）。
3. **不会自动去重**。同一个组合存两次就是两个组件（可能参数不同）。让用户自己删。
4. **组件不是「模板 + 参数」**。插进来的是一份拷贝，改一个不影响另一个。

## 7. 以后可以怎么长

- **从组件库拖到画布**（现在是「插入到中央」，拖更自然）
- **组件带参数**：存的时候把某个数标成「参数」（比如 θ），插入时弹一个小表单——但那一步要小心，别让它变成「预置场景」
- **导出 `.json`**：一个组件一个文件，可以发给同事
- **组件来源标记**：从哪道题 / 哪个场景存出来的，方便回忆

## 8. 验收

```bash
npx vitest run tests/components.test.ts   # 18 项：抽取 / 扩张 / 插入重映射 / 持久化 / 上限
node scripts/shots-draw.mjs               # 25 项，其中 3 项是「存 → 面板 → 插入」
```
