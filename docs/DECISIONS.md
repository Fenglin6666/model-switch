# 关键取舍：为什么这么做，以及哪些结论被推翻了

> 这一篇只回答两个问题：**为什么这么做**、**哪些当初的判断是错的**。
> 不记流水账（每版改了什么看 `git log`），也不重复测试数字（那是 [PHYSICS.md](PHYSICS.md)）。
>
> 数字都来自本仓库的测试或 `npm run validate`。

---

## 1. 物理与数值

### 1.1 半圆槽：课本式推理错了，可移动槽也回到等高

早期架构文档写「槽可移动 → 动量被分走 → 小球到不了等高」。**仿真推翻了它。**

光滑半圆槽、小球不脱离的前提下：小球到右侧最高点时，相对槽的速度沿竖直方向（槽在该点切线竖直），
所以小球的水平速度 = 槽的水平速度；系统水平动量为 0 → 两者水平速度都为 0 → 动能全部转为势能 → **h = h₀**。

| | 最高点 | 与初始差 | 槽位移 | 水平动量 |
|---|---|---|---|---|
| 槽固定 | 0.9564 m | 0.00% | 0 | 不守恒（外部支撑力） |
| 槽可移动 | 0.9565 m | +0.01% | −0.265 m | \|p\| < 0.01，守恒 |

**产品决策**：不删这个场景，改成「推翻直觉」的样本——标题《半圆槽：槽会被推走吗》，文案直接写
「你以为球到不了等高，其实到了；变的是槽的位置」。**工具的价值不是确认课本，而是让你看见自己错在哪。**

### 1.2 轨道不用碰撞链，用理想约束

球在圆弧上用多边形/链碰撞会**持续损失机械能**，且损失与步长无关、只与分段数有关（20 段 31%、40 段 19%、60 段 13%）。
这是几何性的：每跨过一条弦，法向速度方向被投影一次。细化到 1° 仍有 2–3%。

改用 `track` 理想约束：`DistanceJoint` 把球心锁在半径 `R − r` 上，每子步读关节反力——
需要「拉」球时（法向力 < 0）销毁关节 = 脱离；脱离后要先远离 8 mm 才允许重新接上（避免贴面抖动）。
临界速度误差从 3% 降到 **0.24%**。代价是弧本身不生成碰撞 fixture（只留底座/支柱）。

**同一个道理适用于所有「每步投影一次」的曲面接触**：凡是靠离散段近似曲面，都会稳定漏能量。

### 1.3 洛伦兹力必须用速度旋转

每帧 `applyForceToCenter(qv×B)` 在 10 圈后半径漂移 **+12.5%**（1/240、2 substeps），减小步长只能线性改善。
原因：洛伦兹力永远垂直于速度，是「陀螺力」，显式积分每步把速度向量拉长 `sqrt(1+(ωdt)²)` 倍。

改为速度旋转（Boris pusher 的纯磁场形式）：`θ = −(q/m)·Bz·dt`，模长严格不变，漂移 **0%**。

⚠️ 量级警告：真实比荷下回旋周期 ~1e-7 s，1/240 步长连一个周期都采不到。磁场场景**必须用教学比荷**
（q/m ≈ 1）并在 UI 里明说，否则得到一个物理上无意义的动画。

### 1.4 投影公式里 z 的符号反了

原式 `v = base·sinε − z·cosε` 会让 z 越大越靠下，整个场景上下颠倒（第一版半圆槽画成了「∩」）。
重推为 `v = base·sinε + z·cosε`，`d = base·cosε − z·sinε`；反解同步改。`camera.test.ts` 的 13 个往返/朝向测试锁住这点。

### 1.5 启动沉静期（settle）

形状刚好放在地面上时，Planck 的位置修正会把物体顶起约 5 mm（linear slop）。对半圆槽这种能量很小的系统，
这会让机械能基准直接跳 5%，触发守恒判据误报。

处理：`world.settle`（默认 0.12 s）。这段时间**能量类判据不取基准**，但接触/脱离类判据**照常**从 t=0 开始
（否则低速小球一开始就脱离的情况会被漏掉）。

### 1.6 弹簧用真实力，不用软约束

Planck `DistanceJoint` 的软约束实测能量漂移 ~10%。改成每子步施加真实力 `F = k(l−l₀)`（可带阻尼），
并在监视器里补 `½k(l−l₀)²`，守恒漂移降到 0.7%。绳/杆/铰链仍用关节（理想约束不做功）。

### 1.7 小球按实心球算（I = 2/5）

2D 圆在 Planck 里默认是圆盘（I = 1/2），但高中「小球」的默认假设是实心球 → 改成 I = 2/5，
滚动加速度 5/7·g·sinθ（圆盘是 2/3）。

## 2. 架构

### 2.1 `params` + `layout()`：让几何参数也能用滑杆

θ 一改，斜坡几何、滑块位置、初速度方向全变，一个 JSON Pointer 改不动。所以场景带
`params: Record<string, number>`，滑杆绑到 `/params/theta`；预置场景带**确定性**的 `layout(scene)`，
在「重置 / 改参数」时把 params 展开成几何。

- 分享出去的场景带 `meta.preset`，打开后仍能认出预置，滑杆继续生效；
- **直接拖动物体不触发 layout**（否则会被弹回去），下次改参数才重新展开。

### 2.2 `edits`：手动改动要能活过 layout

检查器的写入同时记到 `scene.edits`（按 body/constraint id）。预置布局、分享解码之后都调 `applyEdits`
把用户改的字段盖回去。否则改 θ 会把用户拖过的位置冲掉。

### 2.3 精度档只影响渲染采样

圆、矩形用精确形状（Planck Circle / Polygon），不做多边形近似；圆弧、贝塞尔只在**渲染**上采样；
渲染几何按 Shape 缓存（WeakMap），编辑时重建，渲染时不细分。

### 2.4 分享串手写 base64url

小程序没有 `btoa` / `TextEncoder`，所以手写一份 UTF-8 + base64url 编解码，两边共用。
紧凑串只存 `t`（标题）、`p`（params）、`a`（假设）、`e`（编辑）；结构变了才回退完整 JSON（`s1.`）。

### 2.5 LLM 只做决定，不写 Scene

让模型直接吐 Scene JSON 看着最灵活，但它会写出「看着像但跑不起来」的场景，而我们**没有自动判断对错的能力**——
这正好撞在产品最怕的事上：给一个错模型，学生还以为是对的。

所以 LLM 只能三选一：**选一个已有场景 + 填参数**（走 `layout()`，几何一定合法）、
**用基元拼阶段**（走 `buildChain()`）、**明确说建不了**。三种都落到同一条 `ParseResult` 契约，
上层 UI 和题库状态一行都不用改。细节见 [AI.md](AI.md)。

### 2.6 AI 必须能失败得比没有 AI 更好

接 AI 的典型翻车方式是「配了之后反而更容易出错」。所以三道保险：
没 key → 规则解析；请求失败 → 提示 + 回退规则解析；模型说建不了 → **不回退**（回退等于推翻它的判断）。
`shots-bank.mjs` 里有一条断言塞假 key，要求照样建出模型。

### 2.7 端口：约束连「接点」，不连坐标

原来约束连的是 `Anchor = { bodyId, local }`——一个裸坐标。三个后果：
「把绳接到球的上端」要先算出 `(0, r)`，而 agent 并不知道 r；组件沉淀后坐标跟着物体漂；接错了没人发现。

借 Modelica 的 **connector** 概念：约束连在**端口**上。

- 几何派生（`center/top/bottom/left/right/四角`）所有物体都有，不用声明；
- 语义端口（`axle` 转轴 / `hook` 挂钩）写在 `body.ports` 里，让「电机接在轴上」有名字可指；
- `Anchor` 变成三选一：`{bodyId, port}` / `{bodyId, local}` / `{world}`，旧场景不用改。

真正的好处不在写法好看，在**可校验**：端口不存在能被确定性抓出来（`dangling-port`），
而这正是 agent 最容易犯的错——它不知道场景尺度，凭坐标写必然错位。

### 2.8 结构校验：自由度分析（借 Modelica 的相容性分析）

Modelica 里「方程数 ≠ 变量数」意味着欠约束或过约束，模型要么解不出来要么解出无意义的结果。
刚体系统里对应的量是**自由度**：动态体 3 个（锁转动 2 个），每条约束消去 1–2 个。

```
连通分量内 DOF < 0 → 过约束（冗余约束，planck 会做最小二乘，通常还能跑但会变软/抖）
              DOF > 0 → 欠约束（会自由运动，多数是有意的，只报 info）
```

为什么必须做确定性校验，而不是「让模型自己看看对不对」：有实证——LLM 判断仿真结果不如人工
（见 [RESEARCH.md](RESEARCH.md)）。所以正确性只能落在可计算的东西上：引用是否悬空、
几何是否退化、约束是否冗余。

`analyzeScene()` 是纯函数，Node 里能跑，所以 agent 出招后可以**自己验算再交付**。

> 副产品：它抓出了一个真实的语义坑——**质点默认 `fixedRotation`**，所以「销钉 + 质点」等于完全钉死，
> 不会摆动；「马达 + 质点」直接无效。这类错不报出来，用户只会觉得「怎么不动」。

### 2.9 权限分层：运行时只给数据，开发时给代码

| 层 | 给什么 | 能存/分享/编辑 | 结论 |
|---|---|---|---|
| L1 数据 | 基元 + 参数（现在） | ✅ | 主体 |
| L2 力法则枚举 | 加 variant（浮力/变质量/速度相关摩擦） | ✅ | **该做** |
| L3 受限表达式 | 力法则的表达式树 | ⚠️ 可存，但没滑杆 | 后手 |
| L4 引擎直连 | 任意 JS / planck API | ❌ 全塌 | **不做** |

**为什么 L4 不做**：Scene 是 JSON 这件事支撑着分享串、建模库、撤销、判据 headless 跑、截图验收可复现、
小程序端。一旦产出里含代码，这六样同时塌掉；而且**用户改不了**——回调函数没有滑杆可调。

**为什么 L3 也不急**：表达式树才是"约束下表达"的正确形态。"受限 JS"还要 parser + 沙箱，
而且给 `a*b+c` 里的 `c` 做一根滑杆得反查 AST；表达式树天然就是 AST，编辑就是改字段。
**约束落在类型上，表达力落在算子集上，可编辑性落在叶子上——三者不冲突。**

细节见 [AGENT.md](AGENT.md)。

### 2.10 属性集封闭，所以表驱动可行

「agent 造任意东西 + 关键数值可调」的瓶颈不在零件表，在**面板是写死的**（`renderBodySheet` 353 行、12 根滑杆）。

表驱动的前提是**属性集封闭**：高中物理的物理量大概二十来个（质量/位置/角度/速度/角速度/摩擦/恢复系数/
转动惯量/电荷；绳长/k/l₀/阻尼/马达转速/扭矩/导轨行程；场强/方向/点源强度；n/T/P₀/V；k/G/阻力系数），
列得完。

而电路板是**开放**的：每加一种器件就带一组新属性（电阻的容差、MOSFET 的阈值电压、运放的增益带宽积……），
表会无限长。所以"不做电路"不是暂时，是**架构上不该用同一套表**——真要做，形态是领域包（每个领域自带属性表 + 机制集）。

判据：**21 年 4462 道真题里没出现过的属性，就不进表。**

**已落地**（`core/body-fields.ts`）：一张表管三件事——面板渲染、面板高度、泛型 setter。
原来「加一个属性」要改三处（加一段 UI、改 `sheetHeight()` 的高度算式、补一个 setter），
忘掉任何一处就会出现「滑杆画到面板外面」或「点了没反应」。现在加一行表就行。

顺手补上了原来**根本没有滑杆**的三个属性：质量、线性阻尼、角速度
（质量以前只在信息行显示 `m 0.20 kg`，改不了）。

表里只放 UI 元信息，**字段定义仍在 `Body` 类型里**——两处定义一定会漂。
副作用（角度要顺手把物体抬出地面、摩擦要同步 `params.mu`）留在 App 的 setter 里：
**表管"显示什么"，setter 管"改完还要做什么"。**

## 3. 产品

### 3.1 判据不判对错

`CriterionResult.pass` 只表示「条件是否被检测到」，不表示「答对/答错」。UI 用「已发生 / 未发生」
「守恒 / 不守恒」，不用红绿对错。

### 3.2 不做 A/B 对照

A/B 是**伪需求**：学生容易只看两个动画而不建模，而且「改了什么」被藏在两个世界之间，反而增加认知负担。
物理教学真正需要的是**先按题目假设定模型，再改一个条件看结果**。

替代：预置场景按题目假设定默认（滑块/小球、光滑/粗糙、固定/可移动、有无阻力），解析器把假设写进
`params`，UI 用可点 chip 让用户改。

### 3.3 三个不做 + 一条产品原则

1. **不做课件**——位置被希沃 + NB 占住（数据见 [RESEARCH.md](RESEARCH.md) §4）
2. **不做「讲法」**——不替老师决定怎么讲
3. **不做白板**——批注只做「指出某处」（见 [DRAWING.md](DRAWING.md) §6）

由此确立的原则（比上面三条更重要）：

> **产品只提供「物理情境」，不提供「怎么讲」。**
> 判据：新增功能若在表达「先这样、再那样」→ 不做；若在扩展「这个情境能被怎么摆弄」→ 做。

这条原则会否掉很多东西（课件、讲法、教学步骤、知识点串讲、习题课流程），**是有意为之**。

### 3.4 核心指标是 T，不是留存

既然不做课件也不做讲法，「课堂即时建模太慢」这个问题**没有被产品结构解决**，只能靠**把建模本身变快**。
所以核心指标是：

> **T = 从「我手上有这道题」到「模型在屏幕上能拨」的秒数。**
> 课堂可接受 ≤ 10 秒；备课可接受 ≤ 60 秒。

T 的当前构成（估）：粘贴文字 15–30 s · 解析 < 0.1 s · **生成后纠错 30–120 s**（被忽略的最大成本）·
图片识别未实现（∞）。

### 3.5 外观即语义，而不是开关

「固定 / 可移动」不做两态开关，用剖面线区分。理由：**开关是「让用户操作概念」，外观是「让用户看见事实」**——
用户不用先知道有这个分类，上课时也不用点开面板确认。细节见 [DRAWING.md](DRAWING.md) §5。

### 3.6 组件由使用产生，不预置

编辑器永远追不上「两个球 + 一根绳 + 一个斜面」这种临时组合，而且每加一个预置组件都在赌「老师会不会用」。
反过来，**用户自己知道哪一坨好用**——做出来一次就能存下来。细节见 [COMPONENTS.md](COMPONENTS.md)。

## 4. 平台

- **先做 Web 壳**：交接文档写「先做小程序先上线」，但本机没有微信开发者工具，无法编译/真机预览。
  硬写一个无法验证的壳，风险高于价值。所以先把平台无关的三层做完整，Web 壳只负责 canvas + 指针 + 分享。
- **小程序做分发端，不承担备课编辑**：备课在 Web（键鼠、大屏、能存文件）；小程序只负责
  「打开即场景」和「转发给班级群」。学生端倾向只读（误改后得到错结论，比看不到更糟）。
- **画布全 canvas，无 DOM**：所以属性面板只能拿别人的「设计模式 + 数据结构」，不能 import React 组件。
- **AI 走 BYO-key + 转发层**：浏览器直连厂商接口过不了跨域预检（实测 OPTIONS 不回 ACAO），
  所以默认端点是一个相对路径，由 Vite（开发）或用户自己的代理（生产）转发。
  服务端**不存 key**，只透传 `Authorization`——这样零后端和「不内置凭据」两条都能守住。
  小程序端不支持（无法配置域名白名单），与「小程序做分发端」的定位一致。
- **不要求「小程序也能分享」**：小程序 1024 字符的分享 path 一直在压着设计（要不要让力树进 `p1.`、
  批注能不能进 Scene）。Web 的 URL 能到 64KB，`s1.` 完整 JSON 才 4.6 KB——**接受 Web-only 分享，
  表达力就不再受这条限制**。这是明确取舍，不是妥协：老师备课本来就在电脑上。

## 5. 被推翻的结论

| 当初的判断 | 为什么错 | 现在 |
|---|---|---|
| 槽可移动时小球到不了等高 | 水平动量守恒 → 最高点两者水平速度都为 0 → h = h₀ | 等高（[§1.1](#11-半圆槽课本式推理错了可移动槽也回到等高)） |
| 折线和圆弧一律用胶囊碰撞 | 弦近似每步投影一次，能量稳定漏 13–31%/2s | `track` 理想约束 |
| 洛伦兹力每帧加 `qv×B` | 陀螺力，显式积分线性累积漂移 12.5% | 速度旋转，0% |
| 投影 `v = base·sinε − z·cosε` | z 符号反了，场景上下颠倒 | 改为 `+ z·cosε` |
| 2D 圆用默认 I = 1/2（圆盘） | 高中「小球」默认是实心球 | I = 2/5，滚动 5/7·g·sinθ |
| A/B 对照是核心能力 | 学生只看动画不建模；「改了什么」被藏起来 | 删掉，改按题目假设 + chip |
| 找临界是差异化功能 | 单场景二分搜索，用户不需要「自动找翻转点」，自己拖滑杆更直观 | **v5.10 整体移除**（判据保留） |
| 传送带值得优先做（竞品有） | 全量 4462 题里只有 0.6% | 降到 P2（[RESEARCH.md](RESEARCH.md) §1.4） |
| 空白画布是主入口 | 老师手里先有题，不是「我想建个模」 | 题目 → 建模是主入口 |
| 3D 观察层值得做 | 教学上侧视更好测量，交互/视觉成本没有对应收益 | v3 回退到 2D |
| `belt` / `motor` / `pin` 可以先声明着 | 声明了不实现，类型就在撒谎：`parseLibrary` 会留着它们，用户以为能用 | 已实现（传送带用 planck 的 `setTangentSpeed`） |

> **教训**：用竞品功能当需求证据是不可靠的（传送带）；用课本式定性推理代替仿真也是不可靠的（半圆槽）。

## 6. 已废弃的方案

| 方案 | 为什么废弃 | 替代 |
|---|---|---|
| **条件表单**（选情境类型 → 填参数 → 出模型） | 做过一版又删了：它把「建什么」变成了一道选择题，而老师手里已经有题 | 题目 → 建模 + 手绘 |
| **预置组件库**（「+」面板：点电荷/天体/碰撞球/气缸/滑轮） | 我们猜不准老师要什么；每加一个都在赌 | 组件由使用产生（存为组件） |
| **场景集 `c1.`**（一个链接装 6–8 个模型） | 技术上可行（实测 `p1.` 平均 117 字符），但零后端下「本地建模库 + 文件夹」更实用 | 本地建模库 |
| **面板 schema 驱动**（一套 schema 自动生成控件） | 检查器最终按「选中什么显示什么」写死，比通用 schema 短得多也更好用 | 手写检查器 + `core/params.ts` 参数表 |
| **「讲法」复用单位**（一个模型 + 参数步进 + 每步一句话） | 违反「不提供怎么讲」 | 作废，改成「组件可复用」 |
| **3D 轨道相机 + 挤出渲染** | 教学侧视更好，成本高收益低 | 2D 正交侧视 |
| **首页示例卡片墙** | 18 个示例是给生成器当落点的，不是给用户逛的 | 题库首页 |
| **L1 结构化批注**（箭头/文字/圈 + 序列化） | 一个标注约 60 字符，5 个就把分享预算砍到 2 个场景 | 只做 L2 临时墨迹 |
| **1D 弧长路径求解器**（myPhysicsLab 那条路） | 7–10 人日的架构级改动，现有 `track` 已把临界误差压到 0.24% | 暂不做，等轨道精度真成问题 |
| **内置一个 API key 给所有用户用** | 仓库是 public，key 会立刻公开；而且按次计费与「完全免费」冲突 | 改成 BYO-key（用户自己填，只存本机） |
| **让 LLM 直接输出 Scene JSON** | 模型会写「看着像但跑不起来」的场景，我们没法自动判断对错 | 只让它做决定（选场景 / 拼阶段 / 拒绝） |
| **一键跳到临界点 / 找临界** | 都是在**替用户做判断**。用户要的是「建模 + 能交互」，临界自己暂停就能找到；
  自动扫参数还把「为什么翻」藏在黑箱里 | 只保留判据（翻没翻看得见）+ 暂停 + 拖参数。2026-10-26 再次确认不做 |
| **保留离线规则解析作为兜底** | 两套生成器 = 两套边界，同一个按钮"有时行有时不行"；规则只认 8 类原型，覆盖率 11%，给出的确定性是假的安全感 | **2026-10-26 整体删除**（`core/problem.ts`）。只剩 AI，失败落到编辑器手动搭 |

## 7. 仍待验证

- **老师会不会在课堂上打开一个工具**：只需问 3–5 个物理老师「你上一次讲临界问题是怎么讲的」，
  不是问要不要「讲法」。
- **自动建模的覆盖率能不能过 10%**：这是产品生死线（[RESEARCH.md](RESEARCH.md) §0）。
- **小程序真机在教室老旧设备上的帧率**：桌面数据 84–119 fps，真机没测。
