# 批注：在模型上「指」给学生看

> 需求：建模建好了，老师要讲给学生，希望在模型旁边书写。
> 判断：**应该做，但要做「批注」，不做「白板」**。而且有一个体积硬约束必须先认。
>
> **状态（2026-10-24）：L2 临时墨迹已实现**（`packages/render/src/ink.ts` + `packages/ui/src/app.ts`）。
> 验收脚本 `scripts/shots-ink.mjs` 9/9 通过；Web 407.55 KB / gzip 109.20 KB（+2 KB），小程序 407.1 KB。
> 实现与本文档的差异：**线宽从 2.4px 改成 3px**（2.4 在投屏上看不清）；其余按设计执行。

---

## 1. 先说结论：做，但边界要窄

**为什么该做**：物理课的核心动作是「指着某处说」。现在老师只能拖动物体或口头描述，缺一个**指**的动作。没有它，老师就得切到希沃或拿粉笔——这违反「轻量高效」。

**为什么不能做成白板**：一旦做笔迹，需求会立刻膨胀成颜色 / 粗细 / 图层 / 橡皮 / 导出 / 撤销。那是希沃的地盘（见 `POSITIONING-REVIEW-COURSEWARE.md`），而且会把一个建模工具变成白板工具。

**边界判据**（沿用 `DECISIONS.md` §30「只提供情境，不提供怎么讲」）：

| ✅ 是批注 | ❌ 不是批注 |
|---|---|
| 箭头指向某个物体 | 板书推导过程 |
| 圈住某个区域 | 分步骤讲解 |
| 在旁边写一个数值 | 写一大段文字 |
| 标一句结论 | 画完整的解题流程图 |

**一句话**：批注是「指出情境里的某处」，不是「把课讲一遍」。

---

## 2. 一个必须先认的硬约束：体积

`p1.` 紧凑串现在是 **117 字符**（18 个场景平均），场景集能装 8 个。

如果批注进 Scene，一个结构化标注（短键 + 定点量化）约 **60 字符**：

```json
{"k":"a","f":[120,50],"t":[120,150],"l":"F"}
```

| 场景 | `p1.` 长度 | 场景集能装几个 |
|---|---:|---:|
| 无批注 | 117 | 8 |
| 5 个批注 | ~417 | **2** |

**自由笔迹更糟**：一笔 20 个点 ≈ 120 字符，5 笔 = 600 字符。

**所以：带批注的场景基本进不了场景集。** 这不是设计取舍，是 1024 字符上限决定的。

---

## 3. 分三层，按「体积 × 持久性」切

| 层 | 内容 | 体积/个 | 进 Scene？ | 用途 |
|---|---|---|---|---|
| **L1 结构化批注** | 箭头、文字、圈、框 | ~60 字符 | ✅ 可选 | 预标重点、标数值、标结论 |
| **L2 临时墨迹** | 自由笔迹 | ~120 字符/笔 | ❌ 不存 | 课堂即时草图（讲完就擦） |
| **L3 不做的** | 颜色、粗细、图层、荧光笔、导出图片 | — | — | 白板功能 |

**先做 L2，再做 L1。** 理由：
- L2 不碰序列化，是纯渲染 + 手势，2–3 人日就能用
- L1 要改 Scene 类型、序列化、分享、场景集预算，牵动面大
- 而「课堂上临时圈一下」是最高频的需求，L2 就够

## 4. 四个设计决定

### 决定 1：点存世界坐标，线宽存屏幕像素

```
点坐标 → 世界坐标（缩放/平移后跟着模型走）
线宽   → 屏幕像素（不随缩放变粗变细）
```

**如果点存屏幕坐标**，老师缩放一下笔迹就错位——这是最常见的实现错误。

### 决定 2：墨迹画在最上层，且不参与选中

- 渲染顺序：所有物体/轨迹/箭头 → **墨迹** → UI
- 墨迹不可被选中（没有物理意义），但可被橡皮擦擦掉
- 墨迹不参与命中测试（不会挡住物体拖拽）

### 决定 3：批注箭头必须和力箭头区分开

这是最容易出事的地方：老师画一个指向物体的箭头，学生可能以为是力。

| | 力箭头 | 批注箭头 |
|---|---|---|
| 谁画的 | 物理引擎 | 老师 |
| 颜色 | G 灰 / F 橙 / qE 蓝 / T 绿 | **墨色（`ink`）+ 虚线** |
| 有数值 | ✅ | ❌ |
| 会动 | ✅（跟着物体） | ❌（固定在画布上） |

**用虚线 + 纯墨色**，明确「这不是力」。

### 决定 4：命名冲突——`pen` 已被占用

`Tool` 里已经有 `'pen'`，但它是**建地形**的手绘（创建 `polyline` body，会被小球撞到，双击可切分类）。

**批注必须用新名字**，建议 `'ink'`。否则两个语义会互相污染——老师在"手绘"里画一条线，结果多了一块地形，这是现在就可能发生的困惑。

## 5. 交互：一个「批注态」开关

现在画布上的触摸全给了拖拽/旋转/调速度。加笔必须引入模式，否则同一个手势有两种解释。

```
左栏工具轨（现状）：选择 · 连接 · 平移 · 橡皮 ｜ 形状 ｜ 受力 ｜ 速度
加一个：批注（ink）
```

**进入批注态后**：
- 所有单指触摸都是笔
- 双指仍是缩放/平移（保留）
- 工具栏高亮，画布边缘出现一圈细边（表示"在批注态"）
- 再点一次退出，回到选择态

**为什么不做成常驻**：常驻会和拖拽抢手势。老师讲课时按一下进、讲完按一下出，这个动作是可接受的（和 PDF 阅读器的墨迹模式一样）。

**Web 端额外**：鼠标右键拖拽直接画（不进模式），因为键鼠有右键。

## 6. 不做清单

| 不做 | 理由 |
|---|---|
| 颜色选择 | 一种墨色（`ink`）够用；多色会让人以为是标注体系 |
| 粗细调节 | 固定 2px |
| 图层 | 只有一层 |
| 荧光笔 / 半透明 | 会盖住模型 |
| 导出为图片 | 截图工具能做 |
| 笔迹识别成文字/公式 | L2 变动成本，与免费冲突 |
| 把笔迹当物体（有物理） | 那已经是 `pen`（建地形） |

## 7. 成本

| 项 | 状态 |
|---|---|
| 墨迹层：数据结构 + 渲染（世界坐标、屏幕线宽、最上层） | ✅ `packages/render/src/ink.ts`（`drawInk` / `inkHitTest` / `shouldSample`） |
| 手势：批注态 + 单指画 | ✅ `Tool` 加 `'ink'`、`DragState` 加 `{ kind:'ink' }` |
| 橡皮擦墨迹（先擦墨迹再擦物体） | ✅ `eraseAt()` 里先做 `inkHitTest`，半径 14px 换算成世界坐标 |
| 清空 | ✅ 状态条上的「清空」pill（有墨迹时才出现） |
| 换场景自动清空 | ✅ `loadScene()` 里 `this.ink = []` |
| 小程序端真机验证（触摸采样率、丢点） | ⬜ **未做**（壳只转发单指 pointer，双指缩放本来就没有） |
| L1 结构化批注（箭头/文字/圈 + 序列化 + 预算） | 另 4–5 人日 |

**先做 L2 的 3 人日，看老师是否真的会用。** 如果用了，再投 L1。

## 8. 一个我拿不准的地方

**老师真的会在小程序上用手指写字吗？**

- 小程序屏幕小（390×844），手指写字很难看
- 而物理板书的核心是**画受力图 + 写公式**，这两件事在小屏触屏上都别扭
- 可能真实情况是：老师用 Web + 鼠标/触控笔备课和上课，小程序只给学生看

**如果是这样，L2 应该优先做 Web 端**（鼠标/触控笔精度够），小程序端只做"看"。

这一点只能靠问老师：「你上课用触屏还是用鼠标/笔？」——和之前那个「会不会复用讲法」一样，5 分钟能问出答案。
