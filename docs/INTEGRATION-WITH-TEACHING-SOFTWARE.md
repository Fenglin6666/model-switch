# 能不能把物理建模「搬进」老师现有的讲课软件？

> 追问：老师一般用什么软件讲课批注？能不能把建模搬进去？
> 结论：**技术上能，商务上要合作。个人主体现在做不到，但这条路是通的——而且它比我之前判断的更有价值。**

---

## 1. 老师实际用什么（数据）

| 软件 / 硬件 | 体量 | 说明 |
|---|---|---|
| **希沃白板（EasiNote）** | 活跃教师 **700 万**（2025 H1）；累计课件 **15 亿份**；交互智能平板出货份额 **44.5%**（2024）；2025 Q1 智慧黑板中标金额占 **33.99%** | 一体机**预装**，老师打开电脑就在 |
| **鸿合（HiteVision）** | 全球 IFPD 份额约 **18.5%**，国内前二 | 性价比路线，职校/实训用得多 |
| **PPT / WPS 演示** | 最普遍，但无权威使用率数据 | 老习惯，谁都会 |
| 教育 IFPD 前五（希沃、鸿合、海康、海信、安道） | 合计 **85.9%**（2024 出货量） | 硬件高度集中 |

**关键结论：老师的「讲课 + 批注」主要发生在一体机上的希沃/鸿合白板里，而不是浏览器里。**

这也解释了你上一个问题：老师确实有批注工具，而且是**和硬件绑在一起的**。所以在那个场景里我们做批注，是在重复建设——**除非我们搬不进去**。

## 2. 希沃能不能搬进去：能，但要官方配合

希沃有官方插件体系。仓库 [`EasiNote/EasiPlugin.Sample`](https://github.com/EasiNote/EasiPlugin.Sample)（2023-03 创建，**2026-08 仍在更新**）的 README 写明三种插件形态：

| 形态 | 技术 | 适用 |
|---|---|---|
| 配置插件 | 改客户端配置项，开关隐藏功能 | 不是我们要的 |
| **原生插件** | .NET 6 / WPF 程序集注入，可用「整个希沃白板公开的类型和成员」 | 定制性最强，但 C# + 仅 Windows |
| **Web 插件** | **希沃白板内用 CEF 浏览器打开给定网址** | **我们是这条** |

### Web 插件的两个入口

来自 [`EasiNote/EasiNote.ClientWebApi.Documentation`](https://github.com/EasiNote/EasiNote.ClientWebApi.Documentation)：

1. **学科工具扩展** —— 在备/授课的「学科工具」里加一个入口，点开就是你的网页
2. **课件内容元素扩展** —— 用 js API **把内容插入课件**，支持「多媒体元素（图片、音视频）和 **Web 内容呈现元素**」

官方原话：这两个能力「通常配套一起使用，为课件提供更多的内容资源选择」。

**也就是说：技术上，一个网页可以被嵌进希沃的课件页里，并且有 js API 和课件交互。**

文档还说内容页「本质上就是 web 页面，可以使用 F12 唤起控制台进行调试」——这对我们很友好，现有 Web 版几乎可以直接跑。

### 但真实门槛在这里

| 门槛 | 原文/依据 |
|---|---|
| **插件由希沃生成** | 「学科工具扩展插件的配置，由第三方提供参数，**希沃白板开发人员生成最终的插件**」 |
| **需要线下沟通** | 三方账号：「需要双方的账号系统进行开发联调，具体细节需要进行更多**线下的沟通**」 |
| **文档已迁移，需申请** | 旧文档页首写明「本文档项目暂停维护」，指向 `open.seewo.com`（开放平台，需注册申请） |
| **Web 插件「限制极大」** | `EasiPlugin.Sample` README 原文：「限制极大，但比较独立」 |

**这四条合起来的意思是：这不是「开发者自助接入」，是「B 端商务合作」。**

个人主体基本进不去（没有对公账号、没有合同主体、没有联调人力）。

## 4. 两条路，成本与收益

| | **路 A：独立产品**（现在的路线） | **路 B：接入希沃** |
|---|---|---|
| 老师要不要切工具 | ✅ 要 | ❌ 不用 |
| 批注 | 自己做 | **用希沃的** |
| 大屏适配 | 自己做 | **用希沃的** |
| 备课 | 自己的场景集 | 放进希沃课件 |
| 分发 | 小程序 / 链接 | 希沃云课件 |
| 主体要求 | 个人可做 | **需企业 + 商务合作** |
| 周期 | 现在就能做 | 几个月起，且不确定能谈成 |

**路 B 明显更好，但你现在进不去。**

### 一个我认为对的策略

**路 A 是路 B 的门票。**

希沃开放平台要的是「能提供内容资源的第三方」。你现在没有作品、没有老师用户、没有公司主体——申请大概率被拒或石沉大海。

但如果先做出路 A：有真实的老师在用、有几百个能跑的场景、有一篇能被教研员引用的案例——再去谈，性质就变成「我有一批用户想用你的平台」，而不是「我想接你的平台」。

**所以路 A 不是退而求其次，是路 B 的前置条件。**

**但结论不变**：短期内个人主体进不去，所以批注还是要自己做——不是因为它更好，是因为没有别的选择。

## 7. 建议

**短期（现在）**
- 继续路 A：Web 备课 + 小程序分发 + 自己做轻量批注（L2 临时墨迹，3 人日）
- **不要把批注做重**——它是在替希沃补位，不是我们的差异化

**中期（有老师用户之后）**
- 去 open.seewo.com 注册，看申请条件，把「已接入条件」摸清楚
- 攒案例：几个老师、几节课、几百个场景

**长期（有企业主体之后）**
- 申请接入。到那时我们的定位是「希沃缺的物理动态模型内容源」，而不是「另一个白板」

## 8. 一句话回答你的问题

**老师主要用希沃白板（一体机预装，700 万活跃教师）和 PPT 讲课批注。**

**物理建模能搬进希沃**——它支持 Web 插件，可以嵌进课件页、有 js API 和课件交互、内容页就是普通网页。**但插件要希沃官方生成、要线下谈、要企业主体**。PPT 只能放静态图。

**所以现在搬不进去，但这条路是真的。** 先把独立产品做出来，它是将来敲门的凭证。
